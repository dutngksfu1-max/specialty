## 1. 설계 의도 — 왜 이렇게 만들었나

### 1.1 장식이 아니라 결과의 다른 표현입니다

엠블럼은 예쁘라고 붙인 그림이 아닙니다. **4축 결과를 도형으로 옮긴 것**입니다.
DEC-050 이후 화면 히어로는 콘텐츠로 주입되는 유형 선화가 맡고, 이 엠블럼은
고정 크기 저장 이미지에서 결과를 압축해 보여 주는 역할만 맡습니다.
그래서 마크를 보면 네 축이 각각 어느 쪽인지 읽힙니다.

이 원칙을 어기면 (예: 유형마다 임의의 예쁜 아이콘을 배정하면) 엠블럼은
"의미 없는 decoration"이 되고, 이는 `docs/design.md` 16절 금지 패턴에 해당합니다.

### 1.2 색이 아니라 형태로 구분합니다

**유형마다 다른 색을 주지 않습니다.** 16종 전부 같은 색(선=primary, 중심=accent)을 씁니다.

- 색으로 유형을 구분하면 색맹 사용자에게 정보가 통째로 사라집니다
- `AGENTS.md` 5절 — "선택·오류 상태를 색상만으로 표현하지 않습니다"와 같은 원칙입니다
- 형태로만 구분하면 흑백 인쇄에서도 살아남습니다 (연수 자료로 출력될 수 있습니다)

### 1.3 파일이 아니라 코드입니다

16종을 이미지로 만들면 파일 16개 + 다크 모드 대응 + 해상도별 대응이 생깁니다.
SVG를 코드로 그리면 **함수 하나**로 끝나고, 색은 CSS 변수를 타고 자동으로 따라옵니다.
PWA 아이콘을 코드로 생성하기로 한 `DEC-031`과 같은 판단입니다.

## 2. 매핑 규칙 — 축 하나가 시각 요소 하나를 맡습니다

| 순서 | 축 (teacher-style-v1) | 시각 요소 | positive | negative |
|---|---|---|---|---|
| 1번째 | `axis-energy` 힘을 얻는 방향 | **방사선 방향** | 바깥으로 뻗음 | 안으로 모임 |
| 2번째 | `axis-lens` 먼저 눈에 들어오는 것 | **중심 도형** | 각진 마름모 | 둥근 원 |
| 3번째 | `axis-decision` 판단할 때 먼저 살피는 것 | **중심 채움** | 꽉 찬 면 | 테두리만 |
| 4번째 | `axis-rhythm` 일을 굴리는 리듬 | **바깥 링** | 닫힌 원 | 한 곳이 열린 원 |

### 2.1 각 매핑의 뜻

모양은 아무렇게나 고른 것이 아니라 **축의 의미에서 나왔습니다.**

| 시각 요소 | 왜 이 모양인가 |
|---|---|
| 방사선이 **바깥으로** | 교류형 — 에너지가 사람들 쪽으로 뻗어 나갑니다 |
| 방사선이 **안으로** | 몰입형 — 에너지가 안쪽으로 모입니다 |
| 중심이 **각짐** | 실제형 — 사실은 모서리가 분명합니다. 여기까지가 사실이고 여기부터는 아닙니다 |
| 중심이 **둥긂** | 가능성형 — 가능성에는 모서리가 없습니다 |
| 중심이 **꽉 참** | 원칙형 — 기준이 안까지 차 있어 흔들리지 않습니다 |
| 중심이 **테두리만** | 맥락형 — 틀은 있되 안은 그때그때 채웁니다 |
| 링이 **닫힘** | 계획형 — 예측 가능한 하루. 어디로 갈지 이미 이어져 있습니다 |
| 링이 **열림** | 유연형 — 틈을 남겨 둔 하루. 그 틈으로 좋은 순간이 들어옵니다 |

> **교체할 때 지켜 주세요.** 새 모양을 고를 때도 "왜 이 모양인가"에 한 줄로 답할 수 있어야 합니다.
> 답할 수 없으면 그건 decoration입니다.

### 2.2 왜 이 네 요소인가 — 서로 겹치지 않기 때문입니다

링 · 방사선 · 중심 도형 모양 · 중심 도형 채움은 **서로 독립적인 시각 변수**입니다.
그래서 16가지로 조합해도 형태가 뭉개지지 않고 전부 구별됩니다.

겹치는 변수를 고르면 (예: "선 굵기"와 "선 색 진하기") 조합이 늘어날수록
비슷해 보이는 마크가 생깁니다. **새 매핑을 만들 때 반드시 독립성을 확인하세요.**

## 3. 기하 규격

```
viewBox   0 0 120 120
중심       (60, 60)
링 반지름   44,  선 굵기 3
링 열림    위쪽 −56° ~ +56° (112°) 비움, 끝은 round cap
방사선     45° / 135° / 225° / 315° (대각선 4방향), 선 굵기 3, round cap
  바깥형    r 49 → 59
  안쪽형    r 33 → 23
중심 마름모  반대각선 15 (즉 위아래좌우로 15)
중심 원     r 13.5
채움형      fill: 중심색
테두리형    fill: none, stroke: 중심색, 굵기 3
```

**대각선(45°/135°/…)에 방사선을 둔 이유**: 링의 열린 부분이 위쪽(0° 부근)이라
방사선을 수직·수평에 두면 열린 틈과 겹쳐 보입니다.

### 3.1 색

| 역할 | CSS 변수 | 기본값 |
|---|---|---|
| 링 · 방사선 | `--em-line` → `--color-primary` | 세이지 그린 |
| 중심 도형 | `--em-core` → `--color-accent` | 클레이 |

`currentColor`를 쓰지 않고 변수를 거치는 이유: 결과 화면과 저장 이미지에서
같은 색이 나와야 하는데, 저장 이미지는 `html-to-image`가 인라인 스타일로 굽기 때문입니다.

### 3.2 크기별 사용처

| 크기 | 쓰이는 곳 | 확인된 것 |
|---|---|---|
| 132px | 저장 이미지(1080×1350) | 네 요소 모두 또렷 |
| 32px | 목록·요약 | 방사선 방향까지 구별 가능 |
| 20px | 최소 | 링 열림·중심 도형만 구별 (방사선은 뭉갬) |

**20px 미만으로 쓰지 마세요.** 정보가 사라집니다.

## 4. 구현이 지켜야 하는 것

### 4.1 축 id를 하드코딩하지 않습니다 ⚠️ 가장 중요

`TypeEmblem.tsx`는 `axis-energy` 같은 **문자열을 알지 못합니다.**
`definition.axes` 배열의 **순서**로만 매핑합니다.

```
axes[0] → 방사선 방향
axes[1] → 중심 도형
axes[2] → 중심 채움
axes[3] → 바깥 링
```

이유는 `AGENTS.md` 7절입니다 — 새 검사를 추가할 때 `features/`는 **0줄** 고쳐야 합니다.
축 id로 매핑하면 다음 검사에서 엠블럼이 통째로 깨집니다.

### 4.2 축이 4개가 아닐 때도 죽지 않습니다

- 축이 4개보다 적으면 → 없는 자리는 `positive`로 봅니다
- 축이 4개보다 많으면 → 앞 4개만 씁니다
- 축이 0개면 → 아무것도 그리지 않습니다 (`null` 반환)

결과 화면 전체가 엠블럼 때문에 깨지면 안 됩니다.

### 4.3 접근성

- `role="img"` + `aria-label`을 답니다
- `aria-label`에는 **결과 키(pppp 등)를 넣지 않습니다.** 내부 식별자입니다 (`AGENTS.md` 1.1)
- 저장 이미지 안에서는 카드 전체가 이미 `aria-hidden`이므로 중복 라벨을 피합니다

### 4.4 애니메이션

현재 없습니다. 넣는다면 `prefers-reduced-motion`을 반드시 존중하세요 (`AGENTS.md` 5절).
