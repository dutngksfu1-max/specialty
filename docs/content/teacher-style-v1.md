# Content Package 규격 — teacher-style-v1

> 문서 상태: **스켈레톤 (형식 정의만)**
> 최종 수정: 2026-08-19
>
> ⚠️ **이 문서에는 실제 40문항과 16개 결과 텍스트가 아직 들어 있지 않습니다.**
> 이 문서는 "콘텐츠를 어떤 형식으로 채워 넣어야 하는지"를 정의하는 **양식**입니다.
> 실제 내용은 Phase 4에서 별도로 작성해 이 양식에 채웁니다.

## 0. 이 문서를 쓰는 방법 (초보자용)

이 프로젝트는 **엔진(계산하는 코드)과 콘텐츠(문항·결과 글)를 완전히 분리**했습니다.
그래서 문항을 바꿀 때 개발자가 코드를 고칠 필요가 없습니다. **이 문서의 빈칸만 채우면 됩니다.**

작업 순서는 이렇습니다.

| 단계 | 하는 사람 | 내용 |
|---|---|---|
| 1 | 콘텐츠 작성자 | 이 문서의 빈칸(`[ ]` 부분)을 채운다 |
| 2 | 개발자/에이전트 | 채워진 내용을 `src/infrastructure/content/packages/teacher-style-v1/`에 옮긴다 |
| 3 | 자동 | Zod 검증이 형식 오류를 잡아낸다 |
| 4 | 자동 | 검사가 화면에 나타난다 (다른 코드 수정 없음) |

## 3. 축(Axis) 정의 — 4개 (채워 주세요)

각 축은 **서로 반대되는 두 가지 스타일**을 양 끝에 둡니다.
**어느 쪽도 더 좋거나 나쁘지 않아야 합니다.** 두 pole 이름을 나란히 놓았을 때
한쪽이 칭찬처럼, 다른 쪽이 흉처럼 읽히면 다시 씁니다.

### 축 작성 양식 (4번 반복)

```
axisId        : [영문 소문자-하이픈. 예: axis-pace]
name          : [축 이름. 예: 수업 진행 리듬]

positive pole
  label       : [스타일 이름. 예: 차분한 준비형]
  shortLabel  : [좁은 화면용. 6자 이내]
  description : [이 스타일이 어떤 모습인지 1~2문장]

negative pole
  label       : [반대 스타일 이름]
  shortLabel  : [6자 이내]
  description : [1~2문장]

defaultPole   : positive 또는 negative
                ※ 점수가 정확히 0일 때 사용할 기본 방향입니다 (DEC-001)
                ※ 화면에는 '균형'이라고 표시되지만, 결과 프로필은 하나로 확정해야 하므로 필요합니다
                ※ 어느 쪽을 골라도 무방합니다. 고민되면 positive로 두세요
```

### 강도 구간 (확정 — 4개 축 모두 동일, DEC-002b)

| bandId | label | minAbsScore | maxAbsScore |
|---|---|---|---|
| `balanced` | 균형 | 0 | 4 |
| `clear` | 뚜렷 | 5 | 12 |
| `strong` | 매우 뚜렷 | 13 | 20 |

> 축당 문항이 10개이므로 점수 범위는 -20 ~ +20입니다.
> 나중에 실제 강의 결과를 보고 이 숫자만 바꿀 수 있습니다 (코드 수정 없음).

### 축 4개 체크리스트

- [ ] 네 축이 서로 다른 것을 재고 있는가 (겹치지 않는가)
- [ ] 양 끝 중 한쪽이 더 좋아 보이지 않는가
- [ ] 교직 맥락에서 실제로 관찰되는 차이인가
- [ ] 기존 성격유형 검사의 축 이름을 그대로 쓰지 않았는가

## 5. 문항(Question) 정의 — 40개 (채워 주세요)

### 5.1 배분 규칙

```
총 40문항 = 축 4개 × 10문항
각 축의 10문항 중 polarity +1 을 5개, -1 을 5개로 배분합니다.
```

**왜 반반으로 나누나요?**
모든 문항을 같은 방향(+1)으로 쓰면, "그렇다"만 계속 누르는 사람(묵종 편향)의 점수가
한쪽으로 크게 쏠립니다. 반대 방향 문항을 섞으면 이 편향이 상쇄됩니다.

**polarity가 뭔가요?**
- `+1`: "그렇다"고 답할수록 **positive pole** 쪽으로 간다
- `-1`: "그렇다"고 답할수록 **negative pole** 쪽으로 간다

### 5.2 문항 작성 규칙

| 규칙 | 이유 |
|---|---|
| **기존 MBTI 문항을 복제하거나 문장만 바꾸지 않는다** | 저작권 및 제품 정체성 |
| 교실·학교 상황을 구체적으로 담는다 | "나는 계획적이다" ✕ → "학기 시작 전에 한 달 치 수업 흐름을 미리 그려 둔다" ○ |
| 한 문항에 한 가지만 묻는다 | "나는 꼼꼼하고 빠르다" ✕ (두 가지를 묻고 있음) |
| 부정문을 피한다 | "~하지 않는다"는 5점 척도에서 혼란을 준다. polarity로 방향을 뒤집으세요 |
| 40자 내외로 짧게 | 40번 읽어야 합니다 |
| 옳고 그름을 암시하지 않는다 | "나는 학생을 잘 이해한다" ✕ (아니라고 답하기 어려움) |
| 빈도가 아니라 성향을 묻는다 | "일주일에 몇 번" ✕ → "~하는 편이다" ○ |
| 극단적 표현을 피한다 | "항상", "절대" ✕ |

### 5.3 문항 작성 표

아래 표를 40행 채웁니다. `order`는 화면에 표시되는 통 번호(1~40)입니다.

| order | sectionId | axisId | polarity | weight | text |
|---|---|---|---|---|---|
| 1 | `part-1` | `[축]` | `+1` | 1 | `[문항 텍스트]` |
| 2 | `part-1` | `[축]` | `-1` | 1 | `[문항 텍스트]` |
| 3 | `part-1` | `[축]` | `+1` | 1 | `[문항 텍스트]` |
| … | … | … | … | 1 | … |
| 40 | `part-4` | `[축]` | `-1` | 1 | `[문항 텍스트]` |

> `weight`는 **전부 1**입니다. 검증 데이터가 없는 MVP에서 특정 문항에
> 임의 가중치를 주지 않습니다 (`docs/PRD.md` F-4.2).

### 5.4 문항 배분 확인표 (작성 후 채우세요)

| 축 | polarity +1 문항 수 | polarity -1 문항 수 | 합계 |
|---|---|---|---|

## 6. 결과 프로필(ResultProfile) — 16개 (채워 주세요)

축 4개 × 방향 2가지 = **2⁴ = 16개 조합**입니다. **하나도 빠뜨리면 안 됩니다.**

### 6.1 조합 목록

`P` = positive pole, `N` = negative pole. 축 순서는 axes 배열 순서입니다.

| # | 축1 | 축2 | 축3 | 축4 | resultKey (내부용) |
|---|---|---|---|---|---|
| 1 | P | P | P | P | `pppp` |
| 2 | P | P | P | N | `pppn` |
| 3 | P | P | N | P | `ppnp` |
| 4 | P | P | N | N | `ppnn` |
| 5 | P | N | P | P | `pnpp` |
| 6 | P | N | P | N | `pnpn` |
| 7 | P | N | N | P | `pnnp` |
| 8 | P | N | N | N | `pnnn` |
| 9 | N | P | P | P | `nppp` |
| 10 | N | P | P | N | `nppn` |
| 11 | N | P | N | P | `npnp` |
| 12 | N | P | N | N | `npnn` |
| 13 | N | N | P | P | `nnpp` |
| 14 | N | N | P | N | `nnpn` |
| 15 | N | N | N | P | `nnnp` |
| 16 | N | N | N | N | `nnnn` |

> `resultKey`는 **내부 식별자일 뿐 화면에 절대 노출하지 않습니다.**
> 사용자에게는 `title`(결과 제목)만 보입니다.
> 이 키는 MBTI 4글자 코드와 무관한 자체 표기입니다.

### 6.2 프로필 작성 양식 (16번 반복)

```
resultKey        : [위 표의 키]
poles            : { 축1: P/N, 축2: P/N, 축3: P/N, 축4: P/N }

title            : [결과 제목]
                   예시 형태 — "차분하게 리듬을 만드는 교실 운영자"
                   ※ 12~20자 권장. 360px 화면에서 2줄 이내
                   ※ "~형", "~타입" 같은 분류 어미를 피합니다

oneLiner         : [한 줄 설명. 30~50자]

rhythm           : [나의 교직 리듬 — 2~4문장]
                   이 사람이 하루를, 한 학기를 어떤 흐름으로 보내는지

shiningMoments   : [교실에서 빛나는 순간 — 3개 항목]
                   - [항목 1]
                   - [항목 2]
                   - [항목 3]

underPressure    : [바쁠 때 나타날 수 있는 모습 — 2~3개 항목]
                   - [항목 1]
                   - [항목 2]
                   ※ 비난이 아니라 "이럴 때가 있어요" 톤

withColleagues   : [동료와 함께 일할 때 — 2~3개 항목]
                   - [항목 1]
                   - [항목 2]

collaboration
  naturalFit     : [호흡이 자연스러운 스타일 — 2개 항목]
                   - [스타일 설명 1]
                   - [스타일 설명 2]
  needsTuning    : [조율하면 더 편한 스타일 — 2개 항목]
                   - [스타일 설명 1]
                   - [스타일 설명 2]
```

### 6.3 결과 텍스트 작성 규칙

**쓰지 않는 표현**

| 금지 | 이유 |
|---|---|
| "궁합이 좋은 사람 / 나쁜 사람" | 관계를 단정하고 갈등을 만듭니다 |
| "당신은 ~형입니다" | 사람을 상자에 넣는 말투 |
| 등급·순위·백분위 | 검사의 목적이 평가가 아닙니다 |
| "게으른", "우유부단한", "예민한" 등 낙인 | 교사에게 실례가 됩니다 |
| 4글자 코드·MBTI 명칭 | 절대 금지 |
| 과도한 이모지 | 성숙한 톤을 해칩니다 |

**쓰는 표현**

| 권장 | 예 |
|---|---|
| "~하는 편이에요" | 단정 대신 경향 |
| "~할 때가 많아요" | |
| "호흡이 자연스러운 스타일" | 궁합 대신 |
| "조율하면 더 편한 스타일" | |
| 약점을 강점의 그림자로 | "천천히 확인하는 편이라 결정이 늦어질 때가 있어요" |

**`collaboration` 작성 시 주의**

`needsTuning`(조율하면 더 편한 스타일)은 **"이 사람과 맞지 않는다"가 아니라
"이런 점을 미리 이야기해 두면 서로 편해진다"**는 뜻입니다.
구체적인 조율 방법을 한 문장 덧붙이면 강의장에서 대화 소재가 됩니다.

예시 형태:
> "속도를 먼저 내는 스타일과는, 시작 전에 '언제까지'를 함께 정해 두면 훨씬 편해져요."

## 7. 코드로 옮길 때의 구조 (개발자/에이전트용)

```
src/infrastructure/content/packages/teacher-style-v1/
├─ definition.ts   검사 메타 + scale + axes + sections
├─ questions.ts    문항 40개 배열
├─ profiles.ts     결과 프로필 16개 배열
└─ index.ts        조립 + Zod 검증 후 export
```

```ts
// index.ts (형태 예시)
import { assessmentDefinitionSchema } from "@/infrastructure/content/contentPackageSchema";
import { base } from "./definition";
import { questions } from "./questions";
import { resultProfiles } from "./profiles";

const raw = { ...base, questions, resultProfiles };

// 로드 시 1회 검증 — 형식이 틀리면 여기서 즉시 실패합니다
export const teacherStyleV1 = assessmentDefinitionSchema.parse(raw);
```

그리고 카탈로그에 한 줄만 추가합니다.

```ts
// src/infrastructure/content/StaticAssessmentCatalog.ts
const PACKAGES = [teacherStyleV1 /* , collaborationV1, ... */];
```

**이 외의 파일은 고치지 않습니다.** (`domain/`, `application/`, `features/`, `app/` 모두 0줄)

## 8. 자동 검증 항목

콘텐츠를 넣으면 아래를 자동으로 확인합니다. 하나라도 실패하면 `INVALID_CONTENT_PACKAGE` 오류가 납니다.

- [ ] 모든 `question.axisId`가 `axes`에 존재
- [ ] 모든 `question.sectionId`가 `sections`에 존재
- [ ] `question.order`가 1부터 빠짐없이 연속
- [ ] `resultProfiles` 개수 = 2 ^ (축 개수) = 16
- [ ] `resultProfiles`의 `poles` 조합에 중복·누락 없음
- [ ] `intensityBands`가 0부터 최대 절대값까지 빈틈·겹침 없이 덮음
- [ ] `scale.options`에 `centerValue`(3)가 존재
- [ ] `polarity`가 `+1` 또는 `-1`
- [ ] `weight`가 모두 1 (MVP 규칙)
- [ ] 축별 문항 수가 균등 (경고 수준)
