# PRD — 클래스렌즈 (ClassLens)

> 문서 상태: **v0.2 — 강의 아이스브레이킹 경험과 검사별 프레젠테이션을 반영했습니다.**
> 최종 수정: 2026-08-20
> 이 문서는 **제품 요구사항의 SSOT**입니다. 기능 논쟁이 생기면 이 문서가 기준입니다.

---

## T — Task (무엇을 만드는가)

초등교사를 대상으로 하는 **교직 성향·가치관·업무 스타일 탐색 플랫폼** "클래스렌즈"를 만듭니다.
이 제품은 정밀 진단이나 선발 도구가 아니라, **강의 초반의 긴장을 풀고 자기 발견을 동료와 나누게 하는 아이스브레이킹 도구**입니다.

하나의 검사 사이트가 아니라, **검사를 계속 추가할 수 있는 Assessment Platform**입니다.
MVP에서는 검사 1종(40문항)만 제공하지만, 코드 구조는 처음부터 다중 검사를 전제로 합니다.

**이번 MVP의 한 문장 정의**

> 교사가 닉네임과 결과 캐릭터 성별을 고르고 문항에 답하면, 자신의 교직 스타일을 설명하는
> 읽을 만한 프로필 한 편을 받아 보고, 그 결과를 강의 중 동료와의 대화 소재로 쓸 수 있다.

### 절대 규칙 (제품 정체성)

1. 서비스 어디에도 **기존 성격유형 검사의 명칭 · 4글자 유형 코드 · 그 유형명을 노출하지 않습니다.**
   URL, 페이지 제목, metadata, OG 이미지, 공유 문구, 결과 텍스트 모두 포함입니다.
2. 기존 성격유형 검사 문항을 복제하거나 문장만 바꿔 재사용하지 않습니다.
3. 로그인·회원가입이 없습니다. 개인정보를 서버로 보내지 않습니다.
4. 결과는 "검사 결과표"가 아니라 **읽는 프로필(editorial profile)**입니다.

## C — Context (왜 필요한가)

### 사용 맥락

강사(교사 연수 강의자)가 초등교사 대상 강의에서 다음 용도로 사용합니다.

| 용도 | 강의 중 역할 |
|---|---|
| 아이스브레이킹 | 강의 초반 참여를 여는 활동 |
| 교사 자기이해 | "나는 어떤 방식으로 교실을 운영하는 사람인가" |
| 동료 간 대화 소재 | 결과를 서로 보여 주며 스타일 차이를 이야기 |
| 강의 참여형 콘텐츠 | 스마트폰으로 즉시 참여, 설치·가입 없이 |

### 사용자

**Primary — 참여 교사**

- 초등교사. 연령대 20~50대, 스마트폰 사용
- 강의실에서 **10~15분 안에** 검사를 마쳐야 함
- 앱 설치·회원가입에 대한 거부감이 있음
- 화면이 작다(360px급 기기 실사용). 강의실 와이파이가 불안정할 수 있음

**Secondary — 강사(운영자)**

- 강의 전 링크/QR을 공유하고, 강의 중 결과를 화제로 삼음
- MVP에서는 별도 관리 화면이 없음 (Phase 7에서 검토)

**Tertiary — 콘텐츠 작성자**

- 검사 문항과 16개 결과 텍스트를 작성하는 사람 (강사 본인일 수 있음)
- **코드를 몰라도** 문항을 교체할 수 있어야 함 → 콘텐츠 패키지 분리가 필수

### 문제 정의

| 문제 | 이 제품의 대응 |
|---|---|
| 기존 성격검사는 교직 맥락이 없다 | 교실 운영·업무 리듬 중심의 축 설계 |
| 가입·설치 요구가 참여율을 떨어뜨린다 | 닉네임만, 설치 없이 브라우저에서 |
| 강의실 네트워크가 불안정하다 | Local-first + PWA 오프라인 지원 |
| 결과가 사람을 잘 맞음/안 맞음으로 나누면 불편하다 | "함께할 때 잘 이어지는 점 / 미리 맞춰 두면 좋은 점" 표현 |
| 검사를 늘리려면 매번 새로 만들어야 한다 | 범용 엔진 + 콘텐츠 패키지 구조 |

## R — References (제약과 참고 기준)

### 기술 제약

- Next.js App Router 16.x / React 19.2 / TypeScript strict / Turbopack
- Tailwind CSS v4 (CSS-first `@theme`, OKLCH 토큰)
- shadcn/ui (2026-07부터 Base UI가 기본 primitive)
- Zod 4 (콘텐츠 패키지 검증)
- 저장: IndexedDB (`idb`), PWA: `@serwist/turbopack`, 이미지: `html-to-image`
- 배포: Vercel
- **MVP에 서버 DB 없음.** Supabase는 설계에만 반영하고 연결하지 않음

### 설계 제약

- Feature-first Hybrid Clean Architecture (UI → Application → Domain)
- Domain은 React/Next/Supabase/IndexedDB/Vercel에 의존하지 않음
- 점수 계산은 **동기 순수 함수**
- 상세는 `docs/architecture.md`, 시각 규격은 `docs/design.md`, 결정 이력은 `docs/decisions.md`

### 콘텐츠 제약

- 이번 Phase에서 **실제 40문항과 16개 결과 텍스트를 작성하지 않습니다.**
- 개발 중에는 fixture(가짜 문항)를 씁니다.
- 실제 콘텐츠는 `docs/content/teacher-style-v1.md` 규격에 맞춰 별도 전달됩니다.

## 제품 목표

### 성공의 모습 (정성)

1. 교사가 설명 없이도 첫 화면에서 "무엇을 하는 곳인지" 5초 안에 이해한다.
2. 40문항을 도중에 이탈하지 않고 끝까지 마친다.
3. 결과를 읽고 "어, 나 진짜 이런데" 하고 옆 사람에게 보여 준다.
4. 강사가 다음 검사를 추가할 때 개발자가 엔진을 고칠 필요가 없다.
5. 화면을 보고 긴장이 풀리면서도, 성인 교사를 위한 도구라는 신뢰와 완성도를 느낀다.

### 측정 가능한 목표 (MVP)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 검사 완주 시간 | 중앙값 10분 이내 | 세션 startedAt ~ completedAt (로컬 기록) |
| 응답 유실 | 0건 | 새로고침·뒤로가기 후 응답 보존 QA 시나리오 |
| 첫 화면 로딩 | 3G 환경에서 3초 이내 상호작용 가능 | Lighthouse |
| 접근성 | 키보드만으로 전 과정 완주 가능 | 수동 QA 체크리스트 |
| 검사 추가 비용 | 콘텐츠 패키지 폴더 1개 추가, 엔진 코드 수정 0줄 | 코드 리뷰 |
| 첫 화면 이해 | 5명 중 4명 이상이 검사 주제·예상 시간·시작 방법을 5초 안에 설명 | 5초 테스트 |
| 시각 경험 | `성숙함 / 단조롭지 않음 / 교사 맥락 / 편안함` 평균 4/5 이상 | 초등교사 검토 |

> MVP에는 analytics를 넣지 않습니다(DEC-019). 위 지표는 로컬 기록과 수동 QA로 확인합니다.

## User Flow

### 메인 플로우 (참여 교사)

```
[1] 랜딩 (/)
     검사별 표지(Hero) → 제목·짧은 설명 → 닉네임 → 검사 살펴보기/이어서 하기
        │
        │ "검사 시작하기"
        ▼
[2] 검사 소개 (/assessments/teacher-style)
     검사별 대표 그림 · 문항/묶음/시간 · 3단계 진행 설명 · 개인정보/도구 성격 · 안내(Accordion)
        │
        │ "시작"  → 세션 생성 (닉네임·버전 스냅샷 기록)
        ▼
[3] Part 1 (/assessments/teacher-style/run/1)
     상단: 검사 안내 · 현재 묶음 · 응답 수/전체 수 · 분절 진행바 · 저장 상태 · 검사 메뉴
     묶음 표지: 동적 번호 · section 제목/설명 · 전용 선화 모티프
     본문: 10문항 × 5점 라디오 스케일
     하단: [다음 10문항]
        │  (클릭 즉시 IndexedDB 저장)
        ▼
[4] Part 2 (/run/2)  [이전] [다음 10문항]
        ▼
[5] Part 3 (/run/3)  [이전] [다음 10문항]
        ▼
[6] Part 4 (/run/4)  [이전] [결과 확인하기]
        │  40문항 모두 응답했는지 검증
        │  미응답 → 첫 미응답 문항으로 scroll + focus
        ▼
[7] 결과 (/assessments/teacher-style/result)
     닉네임 → 결과 제목 → 한 줄 설명 → 나의 교직 리듬
     → 4축 시각화 → 강점이 드러날 수 있는 장면 → 바쁠 때 나타날 수 있는 모습
     → 동료와 함께 일할 때 → 함께할 때 잘 이어지는 점 → 미리 맞춰 두면 좋은 점
     → [결과 이미지 저장] [다시 검사하기]
```

### 이탈·복귀 플로우

```
검사 도중 이탈 (앱 종료 / 새로고침 / 뒤로가기 / 네트워크 끊김)
        │
        │ 다시 접속
        ▼
랜딩 또는 검사 소개에서 "이어서 하기" 노출
        │
        ▼
마지막으로 응답한 문항이 있는 Part로 복귀. 이전 응답 그대로 유지
```

### 예외 플로우

| 상황 | 처리 |
|---|---|
| 저장된 세션의 검사 버전이 현재와 다름 | "검사가 새 버전으로 업데이트되었어요. 처음부터 다시 시작할까요?" |
| 저장 데이터가 손상됨 (`DRAFT_CORRUPTED`) | "저장된 응답을 불러오지 못했어요. 새로 시작해 주세요." + 초기화 버튼 |
| IndexedDB 사용 불가 (시크릿 모드 등) | 안내 배너 노출 + 메모리 저장으로 동작(새로고침 시 유실 경고) |
| 결과 조회 시 세션 없음 | 검사 소개 화면으로 안내 |
| 미응답 상태로 결과 확인 시도 | 진행 차단 + 첫 미응답 문항으로 이동 |

## 기능 요구사항

### F-1. 랜딩

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-1.1 | 활성 검사 1개면 **설명과 그림의 표지형 2열 레이아웃**, 모바일은 그림→제목→닉네임→CTA 순서. 여러 개면 검사별 테마를 쓰는 반응형 목록 (DEC-041) | Must |
| F-1.2 | 로그인·회원가입 UI가 없어야 함. 닉네임 입력이 로그인처럼 보이지 않아야 함 | Must |
| F-1.3 | 첫 CTA는 실제 시작으로 오해되지 않도록 `검사 살펴보기`. 진행 기록이 있으면 `이어서 하기`를 우선 노출 | Must |
| F-1.4 | 검사 상세 설명은 Modal이 아니라 Accordion/Collapsible | Must |
| F-1.5 | 진행 중 세션이 있으면 "이어서 하기" 노출 | Must |
| F-1.6 | 검사 소개는 랜딩 대표 그림을 반복하지 않고 축 이름·양쪽 성향·전체 응답 척도로 만든 탐색 지도, 3단계 진행 설명, 개인정보·아이스브레이킹 도구 안내를 담으며 모바일 시작 CTA는 안전영역을 고려해 하단 고정 | Must |
| F-1.7 | 검사 시작은 Modal이 아니라 별도 route로 이동 | Must |
| F-1.8 | 검사 설명은 Accordion으로 유지하고, Dialog는 응답 삭제처럼 확인이 필요한 작업에만 사용 | Must |
| F-1.9 | 단일 검사 랜딩은 표지 카드 한 장만 유지하고, 평가 관점·응답 기준·결과 활용은 검사 소개 route에서 제공해 첫 화면의 겹침과 정보 경쟁을 방지 | Must |
| F-1.10 | 「나의 교직 스타일 탐색」은 주 카드와 1단계 미니 정보 카드로 이어지는 카드형 시각 문법을 랜딩·소개·진행·결과에 일관되게 적용 | Must |
| F-1.11 | 랜딩과 검사 소개의 상단 카드는 같은 그림·같은 2열 구성을 반복하지 않음. 랜딩은 표지, 소개는 평가 구조를 미리 읽는 탐색 지도로 역할과 시각을 분리 | Must |
| F-1.12 | 단일 검사 표지는 텍스트 요소의 시작축을 통일하고 설명 노트·통합 정보 레일·참여 영역으로 위계를 나눔. 1024px에서는 제목과 CTA가 안정적으로 보이고 360px에서는 카드 내부 세로 흐름으로 재배치 | Must |

### F-2. 닉네임과 결과 캐릭터 성별

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-2.1 | 인라인 폼. 1~12자. 비워 두면 '선생님'으로 처리 (DEC-009) | Must |
| F-2.2 | 브라우저 로컬에만 저장. 서버 전송 없음 | Must |
| F-2.3 | 결과 화면 상단에 표시 | Must |
| F-2.4 | 결과 화면에서 닉네임 수정 가능 | Should |
| F-2.5 | 닉네임 입력과 같은 참여 영역에서 남성·여성 캐릭터 성별을 실제 radio로 필수 선택. 값은 결과 캐릭터에만 반영하고 브라우저 로컬에만 저장 (DEC-054) | Must |

### F-3. 검사 진행

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-3.1 | 40문항 = 10문항 × 4 Part. Part마다 별도 route (`/run/[part]`) | Must |
| F-3.2 | 각 문항은 1~5 **실제 accessible radio** (`radiogroup` + 화살표 키 이동) | Must |
| F-3.3 | 이 검사에서는 다섯 척도 라벨을 모두 표시. 360px에서는 2줄 줄바꿈을 허용하되 44×44px 터치 영역과 한 줄 배치를 유지 (DEC-043) | Must |
| F-3.4 | 상단에 검사 안내 링크·현재 묶음·응답 수/전체 수·구간별 분절 진행바·저장 상태·검사 메뉴 | Must |
| F-3.5 | 응답은 **클릭 즉시** 로컬 Repository에 저장 | Must |
| F-3.6 | 페이지 이동·새로고침·브라우저 뒤로가기에도 응답 보존 | Must |
| F-3.7 | 미응답 상태로 다음 이동 시 첫 미응답 문항으로 scroll + focus | Must |
| F-3.8 | 버튼: Part1 `[다음 10문항]` / Part2~3 `[이전][다음 10문항]` / Part4 `[이전][결과 확인하기]` | Must |
| F-3.9 | 문항 순서는 콘텐츠 패키지가 정한 고정 순서 (MVP에서 셔플 없음) | Must |
| F-3.10 | Part 이동 시 페이지 상단으로 스크롤 | Should |
| F-3.11 | 각 묶음 시작에 동적 번호·section 제목/설명·전용 선화 모티프를 표시 | Must |
| F-3.12 | 선택 상태는 채운 원·체크·굵기·선택 라벨로 함께 표시하고, 카드 전체 강조는 `focus-within`에만 사용 | Must |
| F-3.13 | 자동 다음 이동을 사용하지 않음 | Must |
| F-3.14 | 검사 메뉴에 `잠시 멈추기 / 처음으로 / 처음부터 다시` 제공. 재시작은 확인 Dialog 후 응답을 삭제 | Must |

## 비기능 요구사항

### 성능

- 첫 화면 LCP 2.5초 이내(4G 기준), 검사 화면 상호작용 지연 100ms 이내
- Part 전환은 클라이언트 내비게이션으로 체감 즉시
- 결과 이미지 생성 3초 이내 (생성 중 진행 표시)

### 접근성

- **키보드만으로 검사 처음부터 끝까지 완주 가능**
- Radio Group 표준 키보드 내비게이션 (←/→/↑/↓, Home/End, Space)
- `focus-visible` 절대 제거하지 않음
- 선택/오류 상태를 **색상만으로** 표현하지 않음 (아이콘·텍스트·형태 병행)
- `prefers-reduced-motion` 존중
- 본문 대비 4.5:1 이상, 큰 텍스트/UI 요소 3:1 이상
- 터치 타깃 최소 44×44px
- Menu와 Dialog는 키보드 조작, `Esc` 닫기, 닫힌 뒤 트리거 초점 복귀를 지원

### 반응형

- Mobile-first. iOS·Android 스마트폰과 노트북을 모두 **1급 사용 환경**으로 지원하며, 모바일을 데스크톱의 단순 축소판으로 만들지 않음
- **360px 폭에서 가로 스크롤이 발생하지 않아야 함**
- Survey는 데스크톱에서도 읽기 폭을 제한 (최대 40rem)
- Landing은 넓은 화면을 활용해도 됨 (최대 72rem)
- 360 / 390 / 768 / 1024 / 1440px와 200% 확대에서 가로 스크롤 0
- iOS Safari·Android Chrome에서 브라우저 주소창 변화, 화면 회전, 가상 키보드가 열려도 핵심 CTA·입력·오류 메시지가 가려지지 않음
- 모바일 고정 CTA는 `env(safe-area-inset-bottom)`을 반영하고, 작은 화면에서는 콘텐츠 끝에 같은 높이의 여유 공간을 확보
- hover 없이도 모든 기능과 상태를 이해할 수 있고, 모든 조작 영역은 최소 44×44px

### 보안 / 프라이버시

- 개인정보를 서버로 전송하지 않음. 닉네임·응답·결과 모두 브라우저 로컬
- 외부 analytics/트래커 없음 (MVP)
- 사용자가 저장 데이터를 스스로 삭제할 수 있음

### 유지보수성

- TypeScript strict. `any` 사용 금지(불가피하면 주석으로 사유 명시)
- 계층 간 import 규칙을 ESLint로 강제
- 채점 로직은 Vitest 단위 테스트 필수 (경계값·동점 케이스 포함)

### 안정성

- 예상 가능한 오류는 typed error code로 관리 (`docs/architecture.md`)
- UI에 기술 오류 문자열을 그대로 노출하지 않음
- 예상하지 못한 route 오류는 Next.js Error Boundary로 처리

## Acceptance Criteria (완료 판정 기준)

### AC-1. 콘텐츠 비노출

- [ ] `grep -rEni "\bmbti\b|\b[EI][NS][TF][JP]\b" src/ public/` 결과 0건
      (단어 경계 `\b` 없이 검사하면 `listPublished` 같은 식별자가 오탐으로 잡힙니다)
- [ ] URL·`<title>`·metadata·OG 태그에 4글자 코드 없음
- [ ] 결과 키는 내부 식별자이며 화면에 그대로 노출되지 않음

### AC-2. 응답 보존

- [ ] Part 2에서 새로고침 → Part 2 응답 유지
- [ ] 브라우저 뒤로가기로 Part 1 → 이전 응답 유지
- [ ] 기내모드(오프라인) 전환 후에도 Part 3~4 진행·결과 확인 가능
- [ ] 탭 종료 후 재접속 → "이어서 하기"로 복귀

### AC-3. 채점 정확성

- [ ] 전부 3점 응답 → 모든 축 0점 → 4축 모두 '균형' 표시, 결과는 `defaultPole` 조합
- [ ] 경계값 4/5, 12/13 에서 구간 라벨이 정확히 바뀜
- [ ] 같은 응답 입력 → 항상 같은 결과 (Vitest 통과)
- [ ] 연속 점수가 결과 스냅샷에 저장됨

### AC-4. 접근성

- [ ] Tab/화살표 키만으로 40문항 응답 + 결과 도달
- [ ] 모든 인터랙티브 요소에 focus 링 표시
- [ ] 선택 상태가 색 외에 형태/아이콘으로도 구분됨
- [ ] `prefers-reduced-motion: reduce`에서 전환 애니메이션 비활성

### AC-5. 반응형

- [ ] 360×640 뷰포트에서 가로 스크롤 없음
- [ ] 5점 척도가 360px에서 잘리지 않고 터치 타깃 44px 유지
- [ ] 1440px에서 검사 본문 폭이 40rem을 넘지 않음
- [ ] iOS Safari·Android Chrome에서 주소창 축소/확장과 세로·가로 회전 시 레이아웃·고정 CTA가 안정적임
- [ ] 가상 키보드가 열린 상태에서 닉네임 입력, 오류 문구, 제출 CTA를 확인하고 조작 가능
- [ ] 768/1024px 노트북·태블릿 구간에서 과도하게 넓은 문장이나 빈 공간 없이 정보 위계가 유지됨
- [ ] 200% 확대에서 콘텐츠 손실·겹침·양방향 스크롤 없음
- [ ] iOS·Android·노트북에서 모든 문항의 질문·척도 라벨이 카드 안에 포함되고 인접 문항과 겹치지 않음

### AC-6. 확장성

- [ ] fixture 콘텐츠 패키지를 하나 더 추가하면 랜딩에 검사 2종이 노출됨
- [ ] 그 과정에서 `domain/`, `application/`, `features/` 수정 0줄
- [ ] 잘못된 콘텐츠 패키지 투입 시 `INVALID_CONTENT_PACKAGE`로 안전하게 실패

### AC-7. 오류 처리

- [ ] 버전 불일치 세션 → 안내 문구 + 새로 시작 경로 제공
- [ ] 손상된 저장 데이터 → 초기화 안내
- [ ] 미응답 상태 결과 확인 시도 → 첫 미응답 문항으로 이동

### AC-8. 검사별 프레젠테이션

- [ ] 등록 토큰이 아닌 색, 외부 URL, 잘못된 section 참조는 콘텐츠 로딩 단계에서 거부
- [ ] `presentation` 없는 fixture도 플랫폼 기본 테마로 렌더링
- [ ] 새 검사 추가 시 콘텐츠 패키지와 카탈로그 등록 외 `features/`·`app/` 수정 0줄

### AC-9. 고도화 경험

- [ ] 네이티브 radio·`fieldset`·`legend`·명시적 `label`과 다섯 척도 라벨이 모두 렌더링
- [ ] 저장 중 이동, 저장 오류, 중단 후 이어하기, 재시작, 미응답 복구 시나리오 통과
- [ ] Dialog `Esc` 닫기와 트리거 초점 복귀, Menu 키보드 탐색 통과
- [ ] 한 화면의 주 시각 요소 1개, 카드 중첩 최대 2단계, 임의 색·반경·간격 0건
- [ ] 랜딩은 표지 카드 한 장만 보이고, 소개에서 네 가지 탐색 관점·응답 기준·결과 활용이 카드 위계로 구분되며 중복 문구가 없음
- [ ] 대표 그림을 포함한 첫 화면 LCP 2.5초 이내이며 레이아웃 이동 없음

## I — Iterate (다음에 다듬을 것)

1. 강의 1회 시범 운영 후 **구간 경계값(0~4 / 5~12 / 13~20) 재검토** — 실제 분포를 보고 조정
2. 결과 텍스트의 톤 조정 (단정적이지 않은지, 교사에게 실례가 되지 않는지)
3. 완주 시간이 10분을 넘으면 Part당 문항 수 또는 문항 길이 재검토
4. 이탈 지점 파악을 위한 최소 로컬 계측 도입 여부 검토 (서버 전송 없이)
5. 검사 2종 이상이 되면 랜딩 정보 구조 재설계

## 용어 정리 (초보자용)

| 용어 | 뜻 |
|---|---|
| MVP | Minimum Viable Product. 핵심만 담은 첫 버전 |
| PWA | Progressive Web App. 웹사이트를 앱처럼 설치하고 오프라인에서도 쓰게 하는 기술 |
| IndexedDB | 브라우저 안에 데이터를 저장하는 공간. 서버가 아니라 사용자 기기에 저장됨 |
| Repository | "데이터를 어디에 저장할지"를 감춰 주는 코드 계층. 저장소를 바꿔도 화면 코드는 그대로 |
| 콘텐츠 패키지 | 문항·결과 글 같은 "내용물"을 코드와 분리해 담아 둔 묶음 |
| polarity | 문항이 축의 어느 쪽을 가리키는지(+1 또는 -1) |
| 동점(tie) | 축 점수가 정확히 0이라 어느 쪽인지 정해지지 않는 상태 |
| SSOT | Single Source of Truth. "이 문서가 기준이다"라고 정해 둔 유일한 원본 |
