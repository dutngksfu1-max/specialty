# Design SSOT — 클래스렌즈

> 문서 상태: **v0.3 — 플랫폼 공통 문법과 검사별 시각 어휘를 분리했습니다.**
> 최종 수정: 2026-08-20
> 이 문서는 시각 디자인의 유일한 기준입니다. 여기 없는 색·간격·반경·동작을 즉흥적으로 만들지 않습니다.

---

## 1. 디자인 방향

### 1.1 플랫폼이 주는 인상

> 잘 만든 에디토리얼 안내물처럼 차분하고, 답을 고르는 순간에는 명료하며, 결과를 읽은 뒤에는 옆 사람과 이야기하고 싶어지는 경험.

클래스렌즈는 정밀 진단이나 선발 도구가 아니라 초등교사 대상 강의 아이스브레이킹 도구입니다. 사용자를 어린이처럼 대하지 않으면서도 긴장을 낮추는 온기와 발견의 즐거움을 제공합니다.

| 원칙 | 적용 방식 |
|---|---|
| 성숙함 | 유아적 캐릭터·교과서식 장식 대신 절제된 에디토리얼 그림과 정돈된 조판 사용 |
| 단조롭지 않음 | 색을 늘리지 않고 장면 그림·section 모티프·번호·선·면의 리듬으로 변화 생성 |
| 명료함 | 화면마다 주 시각 요소 1개, CTA 1개를 우선하고 상태를 텍스트로 설명 |
| 따뜻함 | 웜 아이보리 바탕, 낮은 채도의 세이지, 소량의 클레이·오커 사용 |
| 정직함 | 정밀검사처럼 과장하지 않고 로컬 저장과 도구 성격을 가까운 위치에서 안내 |
| 확장성 | 공통 문법은 공유하되 검사별 색·그림·모티프라는 시각 어휘는 다를 수 있음 |

### 1.2 시각 위계

1. 강조는 크기 → 여백 → 굵기 → 색 순서로 만듭니다.
2. 「나의 교직 스타일 탐색」은 카드형 검사를 핵심 문법으로 씁니다. 주 카드 → 정보·선택 미니 카드의 2단계까지만 허용하고, 장식만을 위한 카드와 3단계 중첩은 금지합니다.
3. 경계는 border를 기본으로 하고 그림자는 히어로·떠 있는 메뉴·Dialog에만 제한합니다.
4. 문항마다 임의 아이콘을 붙이지 않습니다. 질문의 의미를 유도하지 않도록 `01` 번호와 section 모티프만 씁니다.
5. 같은 컴포넌트가 연속될 때 번호, 구분선, 여백, 선택 상태로 리듬을 만듭니다.

## 2. 세 층의 디자인 계약

### 2.1 플랫폼 공통층

모든 검사가 공유합니다.

- 타이포그래피, 간격, 반응형, 접근성, focus, 상태 피드백
- Button, Field, Accordion, Menu, Dialog, Progress, 결과 엠블럼의 기본 구조
- 네이티브 radio와 `fieldset`·`legend`·명시적 `label`
- 저장·오류·완료 상태의 문구와 아이콘 병행

### 2.2 검사 테마 계약층

검사는 콘텐츠 패키지의 선택형 `presentation`으로 시각 어휘를 주입합니다.

```ts
type AssessmentPresentation = {
  version: 1;
  palette: {
    canvas: PresentationColorToken;
    surface: PresentationColorToken;
    primary: PresentationColorToken;
    accent: PresentationColorToken;
    ink: PresentationColorToken;
  };
  heroArtwork: LocalArtwork;
  sectionArtwork: readonly {
    sectionId: SectionId;
    artwork: LocalArtwork;
  }[];
};

type LocalArtwork = {
  src: `/assessments/${string}/${string}`;
  width: number;
  height: number;
  alt: "";
};
```

- 허용 토큰: `sand-50`, `sand-100`, `sand-950`, `sage-50`, `sage-100`, `sage-600`, `sage-700`, `sage-900`, `clay-100`, `clay-500`, `clay-600`
- UI에서는 선택 토큰을 `--assessment-canvas`, `--assessment-surface`, `--assessment-primary`, `--assessment-accent`, `--assessment-ink`로 변환합니다.
- 외부 URL, 상위 경로 이동, 알 수 없는 색 토큰, 중복·누락된 section ID는 콘텐츠 로딩 단계에서 거부합니다.
- `presentation`이 없는 검사는 플랫폼 기본 테마와 코드 기반 기본 모티프를 사용합니다.
- 채점, 응답, 세션 버전과 Domain의 `AssessmentCatalog` 계약에는 프레젠테이션을 넣지 않습니다.

### 2.3 「나의 교직 스타일 탐색」 전용층

- 감정: 긴장이 풀리고, 가볍게 나를 발견해 옆 사람과 이야기하고 싶어짐
- 색 비율: 웜 아이보리 70% / 세이지 20% / 클레이·오커 10%
- 대표 그림: 열린 노트의 한 줄이 교실 문, 창가의 빛, 성인 교사의 느슨한 실루엣으로 이어지는 에디토리얼 드로잉
- 그림 금지: 얼굴이 보이는 학생, 유아적 마스코트, 그림 속 글자, 교과서식 장식, 사진풍, 3D
- 네 section은 24px 그리드·1.75px 둥근 선·같은 곡률의 코드 기반 선화 모티프를 사용합니다.
- 결과 화면의 기존 추상 엠블럼은 유지하며 대표 래스터 그림을 공유 이미지에 넣지 않습니다.

이번 아트 디렉션은 이 검사 전용입니다. 다른 검사는 공통 구조와 상호작용 원칙만 이어받고 자체 프레젠테이션을 선택합니다.

## 3. 색 토큰

### 3.1 Raw palette

모든 색은 OKLCH로 정의하고, 컴포넌트에서는 raw 값을 직접 쓰지 않습니다.

| 계열 | 범위 | 역할 |
|---|---|---|
| Sage | `sage-50` ~ `sage-950` | primary, 선택, focus, 모티프 |
| Sand | `sand-50` ~ `sand-950` | canvas, surface, border, text |
| Clay | `clay-100` ~ `clay-700` | 작은 장면 포인트와 accent |
| Status | success / warning / danger / info | 반드시 아이콘·문구와 함께 사용하는 상태 |

### 3.2 플랫폼 semantic token

| 토큰 | 역할 |
|---|---|
| `background` | 플랫폼 기본 canvas |
| `surface`, `surface-muted`, `surface-inset` | 정보 계층별 면 |
| `border`, `border-strong` | 기본·강조 경계 |
| `foreground`, `foreground-body`, `foreground-muted`, `foreground-subtle` | 텍스트 위계 |
| `primary`, `primary-hover`, `primary-active`, `primary-soft` | 주 행동·선택 |
| `accent`, `accent-soft` | 제한된 포인트 |
| `focus-ring` | 2px focus-visible |

### 3.3 색 사용 규칙

- 본문 대비 4.5:1, 큰 텍스트와 UI 경계 3:1 이상입니다.
- 선택·오류·저장 상태를 색만으로 표현하지 않습니다.
- 보라/파랑 그라데이션과 장식용 다색 그라데이션을 쓰지 않습니다.
- 페이지 canvas는 테마의 단색과 아주 옅은 종이 질감만 허용합니다. 과도한 블러·floating blob은 금지합니다.

## 4. 타이포그래피

- Pretendard Variable local font를 사용합니다.
- fallback: `-apple-system`, `BlinkMacSystemFont`, `Apple SD Gothic Neo`, `Malgun Gothic`, sans-serif
- 본문 최소 16px, 척도 라벨 최소 12px, 보조 정보 최소 13px입니다.
- 한글은 `word-break: keep-all`, `overflow-wrap: break-word`, 제목은 `text-wrap: balance`, 본문은 `text-wrap: pretty`를 기본으로 합니다.

## 5. 간격·폭·반경·그림자

### 5.1 간격

4px 기반 체계를 사용합니다. 허용 단위는 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80px입니다.

- 모바일 페이지 좌우: 20px, 360px 이하 16px
- 태블릿·노트북: 32~48px
- section 간: 모바일 48px, 데스크톱 64~80px
- 카드 내부: 모바일 20px, 데스크톱 24~32px
- Survey 본문 최대 40rem, Landing 최대 72rem

### 5.2 반경 위계

| 토큰 | 값 | 대상 |
|---|---:|---|
| `radius-xs` | 6px | 배지·작은 상태 |
| `radius-sm` | 10px | 입력·보조 컨트롤 |
| `radius-md` | 12px | Button·Menu item·Dialog action |
| `radius-lg` | 18px | 문항·정보 카드 |
| `radius-hero` | 28px | 대표 그림 면과 페이지의 주 hero |
| `radius-full` | 9999px | radio 원과 progress track만 |

버튼·배지·카드에 `radius-full`을 쓰지 않습니다. 40px 반경과 4px 흰 테두리는 사용하지 않습니다.

### 5.3 그림자

| 이름 | 사용 |
|---|---|
| `elev-0` | 기본. border만 사용 |
| `elev-1` | hero 그림, sticky CTA의 얕은 분리 |
| `elev-2` | 떠 있는 Menu, Dialog |

hover에서 카드 전체를 위로 들어 올리지 않습니다. Button·Menu item의 면색 변화로 반응을 보여 줍니다.

### 5.4 카드 덱 문법 — 「나의 교직 스타일 탐색」 전용

- 랜딩 hero, 검사 소개의 핵심 정보, 묶음 표지, 문항은 모두 동일한 1px 선·18px 반경·웜 표면을 공유해 **전체가 카드형 검사**로 읽혀야 합니다.
- 화면의 주 카드는 아래로 6~8px 어긋난 얇은 보조 면 또는 짧은 모서리 선을 가질 수 있습니다. 보조 면은 콘텐츠 카드가 아니며 클릭 가능해 보이지 않아야 합니다.
- 미니 정보 카드는 숫자 탭, 24px 선화 아이콘, 짧은 제목, 한 문단 이하 설명으로 구성합니다. 같은 행에서는 높이와 기준선을 맞춥니다.
- 아기자기함은 마스코트가 아니라 작은 번호 탭, 둥근 선화, 노트의 인덱스처럼 보이는 모서리 표식, 세이지·클레이의 절제된 교차로 만듭니다.
- 카드마다 그림자를 반복하지 않습니다. 주 카드만 `elev-1`, 내부 카드는 border와 면색으로 층위를 만듭니다.
- 모바일에서는 어긋난 보조 면까지 페이지 좌우 여백 안에 포함합니다. 긴 제목과 본문은 카드 높이를 늘리며, 고정 높이·음수 margin으로 겹침을 해결하지 않습니다.

## 6. 공통 컴포넌트

### 6.1 Button

- 최소 높이 48px, icon-only는 44×44px 이상
- 반경 12px, primary / secondary / quiet / danger 네 종류
- loading은 기존 라벨 폭을 유지하고 비활성 이유를 보조 문구로 전달
- 모바일 고정 CTA는 `padding-bottom: env(safe-area-inset-bottom)`을 포함

### 6.2 Field

- label을 placeholder 대신 사용하지 않습니다.
- 도움말 → 입력 → 오류 순서이며 `aria-describedby`로 연결합니다.
- 가상 키보드가 열려도 입력, 오류, CTA가 동시에 확인 가능해야 합니다.

### 6.3 Accordion

- 검사 설명에 사용합니다. Dialog 대체 수단으로 쓰지 않습니다.
- Trigger 전체가 44px 이상이고 펼침 상태는 아이콘 방향과 `aria-expanded`로 전달합니다.
- 한 번에 여러 항목을 열 수 있습니다.

### 6.4 Menu

- 검사 중 `잠시 멈추기`, `처음으로`, `처음부터 다시`를 한곳에 모읍니다.
- 키보드 방향키·Home/End·Esc를 지원하고 닫힌 뒤 Trigger로 초점이 돌아옵니다.
- 파괴적 항목은 구분선과 danger 문구로 구별합니다.

### 6.5 Dialog

- 응답 삭제·재시작처럼 확인이 필요한 작업에만 씁니다.
- 제목, 영향 설명, 취소, 확인을 제공하고 초기 초점은 취소에 둡니다.
- Esc 닫기, backdrop, focus trap, trigger focus return을 지원합니다.

## 7. 랜딩과 검사 소개

### 7.1 랜딩 `/`

- 활성 검사 1개: 데스크톱은 설명/입력과 4:3 대표 그림의 2열 표지, 모바일은 그림 → 제목 → 설명 → 닉네임 → CTA 순서
- 활성 검사 여러 개: 같은 데이터에서 반응형 목록으로 자동 전환
- CTA 기본 문구 `검사 살펴보기`; 진행 기록이 있으면 `이어서 하기` 우선
- 표지 자체를 주 카드 덱으로 구성하고, 문항·묶음·시간 및 `정답 없음 / 가입 없음`은 한 단계의 미니 정보 카드로 정리합니다.
- 활성 검사 1개일 때 랜딩에는 표지 카드 한 장만 둡니다. 탐색 관점·응답 기준·결과 활용은 검사 소개 페이지로 넘겨 첫 화면이 서로 경쟁하거나 겹치지 않게 합니다.
- 표지 카드 안에서만 검사 대상·예상 시간·`검사 살펴보기` 경로를 5초 안에 이해할 수 있게 합니다.
- 그림에는 고정 width/height와 `sizes`를 제공해 layout shift를 방지합니다.

### 7.2 검사 소개

- 랜딩의 대표 그림과 2열 구성을 그대로 반복하지 않습니다. 소개 상단은 제목·설명 영역과 **콘텐츠 데이터로 만든 교직 리듬 탐색 지도**를 나란히 구성합니다.
- 탐색 지도에는 축별 이름, 양쪽 pole의 짧은 이름, 전체 응답 척도를 표시해 무엇을 어떤 방식으로 살펴보는지 시작 전에 이해시킵니다.
- 소개 상단은 랜딩의 카드 덱 그림자 대신 4px 상단 인덱스 선, 좌우 분할 면, `INTRO 01` 번호 탭으로 별도 문법을 사용합니다.
- 3단계: 답하기 → 결과 읽기 → 동료와 대화하기
- 개인정보는 이 브라우저에만 저장됨을 짧고 가까운 위치에 표시
- 정밀 진단이 아니라 대화를 위한 탐색 도구임을 명시
- 상세 문답은 Accordion, 시작·이어하기는 별도 route
- 모바일 CTA는 안전영역을 포함해 하단 고정하고 본문 끝에 같은 높이의 spacer를 둡니다.
- 네 가지 탐색 관점, 답을 고르는 기준, 결과에서 가져갈 내용은 서로 다른 카드 묶음으로 분리합니다. 같은 설명을 hero·진행 방식·Accordion에서 반복하지 않습니다.

## 8. 검사 진행

### 8.1 상단 정보

- 검사 안내 링크, 현재 묶음, 응답 수/전체 수, 4구간 분절 진행바, 저장 상태, 검사 메뉴
- 숫자와 `aria-valuetext`를 함께 제공하며 색만으로 진행을 전달하지 않습니다.
- 모바일에서 2행까지 허용하고, 핵심 진행률과 메뉴는 첫 행에 유지합니다.

### 8.2 묶음 표지

- 동적으로 계산한 묶음 번호, 콘텐츠의 section 제목·설명, 전용 선화 모티프
- 모티프 alt는 빈 문자열이며 제목 정보를 반복하지 않습니다.
- 제목은 `Part 1` 같은 기계적 명칭 대신 사용자가 지금 떠올릴 장면을 알려 주는 짧은 문장으로 씁니다. 설명에는 기준 시점, 답을 고르는 기준, 정답 없음 중 필요한 안내를 담습니다.
- 묶음 표지는 주 카드로 처리하고 `요즘의 나 / 정답 없음 / 자동 저장` 같은 응답 가이드를 짧은 정보 행으로 제공합니다.

### 8.3 Question card

- `<fieldset role="radiogroup">` 안의 `<legend>`가 질문 문장입니다.
- 표시 번호는 전체 순서 기준 `01` 형식입니다.
- 기본은 1px border·18px 반경·그림자 없음, `focus-within`에서만 primary-soft 경계가 나타납니다.
- 선택 결과를 질문 카드 전체 배경색으로 과장하지 않습니다.
- `legend`는 fieldset 경계의 기본 홈에 걸치지 않고 카드 내부의 독립된 질문 영역으로 배치합니다. `fieldset`은 `min-width: 0`, 내부 흐름은 `clear` 처리해 긴 문장·확대 환경에서 척도와 절대 겹치지 않게 합니다.
- 문항 카드의 번호·질문·척도 사이에는 명시적인 구분선 또는 면 전환을 두며, 고정 높이와 음수 margin을 사용하지 않습니다.

### 8.4 Likert scale

- 실제 `<input type="radio">`와 `for`/`id`로 연결한 label을 사용합니다.
- 이 검사는 `전혀 그렇지 않다 / 그렇지 않다 / 보통이다 / 그렇다 / 매우 그렇다`를 모두 표시합니다.
- 360px에서도 선택지는 한 줄, 각 터치 영역 44×44px 이상, 라벨은 두 줄 줄바꿈 가능
- 선택: 채운 원 + check + 굵은 label + 스크린리더용 `선택됨`
- 키보드 화살표 이동과 Space 선택을 브라우저 기본 동작으로 유지하고 자동 다음 이동은 하지 않습니다.
- 다섯 선택지는 하나의 응답 트레이 안에서 각각 작은 선택 카드로 읽히게 합니다. 선택 카드의 폭은 `min-width: 0`, 라벨은 자연 줄바꿈, 트레이는 `overflow: hidden`으로 모바일 돌출을 차단합니다.

### 8.5 저장과 이동

- `저장 중… / 이 브라우저에 저장됨 / 저장하지 못했어요`를 아이콘과 함께 표시
- 겹친 저장은 모두 완료돼야 이동하며 실패 시 현재 화면에서 재시도 가능
- 하단에 이전 묶음·다음 묶음/결과 확인, 상단 Menu에 중단·홈·재시작
- 미응답이면 첫 미응답 질문으로 scroll·focus하고 오류 요약을 제공합니다.

## 9. 결과

- 콘텐츠 순서와 추상 엠블럼은 `AGENTS.md`의 고정 순서를 유지합니다.
- 같은 검사 palette와 선화 문법을 사용하되 hero 래스터 이미지는 반복하지 않습니다.
- 장면 태그에는 의미가 있는 공통 선화 아이콘만 사용합니다.
- Axis 시각화는 pole label, 연속 위치, 강도 문구를 함께 제공해 색에 의존하지 않습니다.
- 공유 이미지는 엠블럼과 토큰 기반 선화만 사용하고 외부 이미지 요청이 없어야 합니다.
- 첫 결과 카드는 닉네임·결과 제목·한 줄 설명·엠블럼·교직 리듬을 한 흐름으로 묶습니다. 긴 리듬 설명을 첫 카드 밖으로 분리하지 않습니다.
- 화면 본문은 `한눈에 보는 나 / 교실에서 드러나는 모습 / 함께 일하는 방식 / 다음 대화로` 네 장으로 묶되, DEC-038의 콘텐츠 순서는 바꾸지 않습니다.
- 데스크톱은 본문 3열·내부 목차 1열의 비율을 사용하고 목차를 sticky로 둡니다. 모바일은 목차를 본문 위 2열 바로가기로 바꿉니다.
- 결과 축은 축 이름, 양쪽 pole, 연속 위치, 현재 방향과 강도를 한 행에서 함께 읽을 수 있어야 합니다.
- 장면 서술은 세 개의 큰 장면군 안에서 2열까지 허용합니다. 문장 하나마다 별도 카드를 만들지 않습니다.
- 별도 결과 삽화를 추가하지 않고 유형 엠블럼을 첫 화면의 유일한 주 시각 요소로 사용합니다. 설명보다 장식이 앞서지 않게 하기 위함입니다.
- 저장·재검사·이름 변경은 결과 본문 뒤의 하나의 마무리 구역에 모읍니다.

## 10. 반응형과 실제 기기

모바일은 데스크톱의 축소판이 아니라 iOS·Android 스마트폰과 노트북 모두를 위한 1급 레이아웃입니다.

| 폭/환경 | 설계 기준 |
|---|---|
| 360px | 최소 지원 폭, 좌우 16px, Likert 5개 한 줄, 가로 스크롤 0 |
| 390px | 최근 iPhone 기준, safe-area와 브라우저 하단 UI 확인 |
| 768px | 태블릿·작은 창, 1열을 유지하되 여백 확대 |
| 1024px | 노트북·가로 태블릿, 랜딩 2열과 Survey 40rem 제한 |
| 1440px | 큰 화면, 콘텐츠 폭을 늘리지 않고 주변 여백으로 집중 유지 |
| 200% 확대 | 콘텐츠 손실·겹침·양방향 스크롤 없음 |

필수 기기 QA:

- iOS Safari와 Android Chrome의 주소창 축소/확장에 `100vh` 대신 필요한 곳에서 `100dvh` 사용
- 세로·가로 회전 후 sticky header·fixed CTA·Dialog 위치 유지
- 가상 키보드가 닉네임 입력·오류·CTA를 가리지 않음
- `env(safe-area-inset-top/bottom)` 반영
- hover에만 정보나 행동을 두지 않음
- 손가락 터치 타깃 44×44px, 인접 타깃 사이 8px 권장
- 긴 한글, 큰 글꼴, 느린 모바일 네트워크와 오프라인에서 레이아웃 유지
- 문항 질문·번호·척도 라벨의 bounding box가 서로 겹치지 않고 모두 해당 fieldset 안에 포함되는지 확인

## 11. 모션

모션의 성격은 **차분하고 따뜻한 반응**입니다. 장식보다 상태와 공간 관계를 설명합니다.

| 토큰 | 시간 | 용도 |
|---|---:|---|
| fast | 120ms | pressed, radio check, 작은 색 변화 |
| base | 220ms | Accordion, Menu, progress |
| scene | 360ms | hero 최초 진입, Dialog 등장 |
| ambient | 6000ms | 대표 배경 선 1~2px 왕복 |

- easing: `cubic-bezier(0.2, 0, 0, 1)`
- 동시에 움직이는 요소는 화면의 1/3 이하입니다.
- hero 최초 진입은 1회만 실행합니다.
- progress는 width/transform, Dialog는 opacity와 4~8px 이동만 사용합니다.
- `prefers-reduced-motion: reduce`에서는 transform, delay, 반복, smooth scroll을 제거하고 즉시 상태를 표시합니다.

## 12. 접근성

- 키보드만으로 랜딩 → 소개 → 전체 응답 → Menu/Dialog → 결과까지 완주
- `focus-visible` 2px outline과 2px offset을 제거하지 않음
- 문항은 `fieldset`·`legend`, 척도는 실제 radio·label 사용
- 상태를 색 이외에 아이콘·문구·형태로 중복 전달
- 본문 4.5:1, 큰 텍스트·UI 3:1 이상
- live region은 저장 상태와 오류에만 제한해 과도한 읽기를 방지
- Dialog Esc 닫기·focus trap·trigger focus return
- 44×44px 터치 타깃, 200% 확대, 스크린리더 순서 확인
