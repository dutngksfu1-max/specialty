## 1. 문제 정의

### 1.1 현재 상태 진단

코드를 확인한 결과입니다.

| 층 | 현재 | 가능한 최대 |
|---|---|---|
| 축 기울기 | 축당 5상태(균형1 + 방향2 × 강도2) → 5⁴ = **625** | — |
| 축쌍 렌즈 | **6쌍 중 1쌍만 구현** (`axis-lens` × `axis-rhythm`) | 6쌍 × 4조합 = 24 |
| 축 순위 | **없음** | 12 |
| 항목 수준 신호 | **없음** | 아래 4장 |
| 고정 유형 | 16개 — 제목·장면·협업·행동 문구 **전부 여기서 옴** | — |

화면을 실제로 지배하는 것은 **16개 고정 텍스트**입니다. 연속 점수는 축 막대 그림에만 쓰입니다.

### 1.2 네 가지 증상과 하나의 뿌리

| 증상 | 뿌리 |
|---|---|
| 가독성이 떨어진다 | 같은 무게의 문단이 계속 이어짐 — **표현 문제** |
| 카드로 묶이지 않아 개별성이 없다 | 항목 경계가 시각적으로 없음 — **표현 문제** |
| 정제되지 않은 말로 구구절절 설명한다 | 조회한 문장을 그대로 이어 붙임 — **구조 문제** |
| 전문성도 인사이트도 없다 | **점수가 해석을 바꾸지 못함** — **구조 문제, 그리고 나머지 셋의 원인** |

표현만 고치면 **예쁜데 여전히 알맹이 없는 화면**이 됩니다. 구조를 먼저 고칩니다.

### 1.3 목표 문장

목표는 아래 두 번째 문장을 만드는 것입니다.

```
현재      "교류형입니다. 사람들과 이야기하며 힘을 얻는 편이에요."
          → 어느 한 문항의 답을 되풀이한 것

목표      "동료와 있는 장면에서는 교류 쪽으로 뚜렷하게 기울지만,
           업무를 처리하는 장면에서는 반대로 갑니다.
           이 둘이 갈리는 분은 많지 않습니다.
           — 근거: 동료 장면 4문항 평균 4.5 / 업무 장면 3문항 평균 2.0"
          → 문항 사이의 관계에서 나온 말
```

두 번째 문장은 **어떤 조회표로도 만들 수 없습니다.** 합산이 버린 정보가 있어야 나옵니다.

## 2. 철학

> **우리는 사람을 분류하지 않습니다.**
> 응답이 만든 좌표를 읽고, **그 좌표에서만 보이는 장면**을 돌려줍니다.

이 문장에서 세 가지 규칙이 나옵니다.

| 규칙 | 뜻 |
|---|---|
| **좌표는 버리지 않는다** | 연속 점수를 이산 유형으로 바꾼 뒤 원본을 버리지 않습니다. 유형은 요약이지 정체가 아닙니다 |
| **보이는 것만 말한다** | 관찰하지 않은 것을 추론해 붙이지 않습니다. 직업·적성·역량은 우리가 재지 않았습니다 |
| **틀릴 수 있음을 함께 준다** | 반박할 수 없는 결과는 검사가 아니라 점괘입니다 |

DEC-038의 **"많이 보여주기가 아니라 정직하게 보여주기"** 를 계승하되, 정직함을 **화면에 보이는 장치**로 구현합니다(5장).

## 4. 해석 모델 (핵심)

### 4.1 3단 파이프라인

```
현재   문항 48개 ──[합산]──▶ 축 점수 4개 ──[조회]──▶ 텍스트
                    ↑
              여기서 문항 사이 관계가 전부 사라집니다

신규   문항 48개 ──[신호 추출]──▶ 신호 5종 ──[조립]──▶ 텍스트
                                    ↑
                        합산이 버리던 정보가 여기 살아 있습니다
```

**신호(Signal)** 층이 이 PRD의 핵심입니다. 다섯 종류입니다.

| ID | 신호 | 무엇을 말하나 | 지금 데이터로 가능? |
|---|---|---|---|
| **S1** | 방향 | 어느 쪽으로 기우는가 | 기존 |
| **S2** | 강도 | 얼마나 기우는가 | 기존 (5구간으로 세분) |
| **S3** | 일관성 | 축 안에서 **자기 자신과 일관됐는가** | **즉시 가능** |
| **S4** | 맥락 분화 | **장면에 따라 달라지는가** | 맥락 태그 추가 후 |
| **S5** | 응답 폭 | 척도를 넓게 썼는가, 가운데에 머물렀는가 | **즉시 가능** |

이 구분이 결정적입니다.

> **S1·S2만으로는 단정밖에 못 합니다.**
> **S3·S4·S5가 있어야 "얼마나 믿어도 되는지 · 어디서 달라지는지"를 말할 수 있습니다.**

응답은 이미 **문항 하나하나 개별 저장**되고 있습니다(`saveResponse`). 쓰지 않고 있을 뿐입니다.

### 4.2 신호 정의 — 계산식

모두 **동기 순수 함수**입니다(`AGENTS.md` 2.2). `async` 금지.

#### S1 방향 · S2 강도 (기존 계승)

```
centered  = 응답값 - scale.centerValue        (1→-2 … 5→+2)
aligned   = centered × polarity               (축 방향으로 정렬)
rawScore  = Σ aligned × weight                (축당 -24 ~ +24)
방향       = rawScore 부호 (0이면 axis.defaultPole)
강도       = |rawScore| 가 속한 구간 (6장)
```

#### S3 일관성 — 축 내 흩어짐

같은 축 12문항의 `aligned` 값이 서로 얼마나 모여 있는지 봅니다.

```
mean      = rawScore / (축 문항 수)
variance  = Σ (aligned_i - mean)² / (축 문항 수)
```

`aligned ∈ [-2, +2]` 이므로 `variance ∈ [0, 4]` 입니다. 절반이 +2, 절반이 -2일 때 최대 4가 됩니다.

| 구간 | variance | 뜻 |
|---|---|---|
| `steady` | 0 ~ 0.8 | 열두 문항에서 비슷하게 답했습니다 |
| `mixed` | 0.8 ~ 1.8 | 문항에 따라 조금씩 달랐습니다 |
| `split` | 1.8 ~ 4.0 | **문항에 따라 크게 갈렸습니다** |

**왜 중요한가**: 같은 `+6`도 "일관된 +6"과 "갈린 +6"은 완전히 다른 사람입니다. 지금은 둘이 똑같은 결과를 받습니다.

> 경계값 0.8 / 1.8은 **설계값**입니다. 검증된 절단점이 아니며, 문서에 그렇게 표기합니다(9.4).

#### S4 맥락 분화 — 장면에 따라 달라지는가

조회표로는 절대 만들 수 없는 문장이 여기서 나옵니다. 다만 **쓸 수 있는 축이 제한적입니다** — 아래 가용성 표를 먼저 보세요.

문항에 `context` 태그를 붙입니다(Phase A 완료). 그런 다음 **축 안에서** 맥락별 평균을 비교합니다.

```
for 각 축:
  for 각 맥락 c (해당 축에 c 태그 문항이 3개 이상일 때만):
      ctxMean[c] = mean(aligned_i)  where context_i = c
  gap = max(ctxMean) - min(ctxMean)
```

**보고 조건 — 셋 다 충족할 때만 말합니다.**

| 조건 | 값 | 이유 |
|---|---|---|
| 맥락당 최소 문항 수 | **≥ 3** | 1~2문항으로 "장면에 따라 다르다"고 말하면 잡음을 해석하는 것입니다 |
| 최소 격차 | **gap ≥ 1.5** | `[-2, +2]` 척도에서 1.5는 방향이 바뀔 만한 크기입니다 |
| 비교 맥락 수 | **≥ 2** | 당연 |
| **맥락 안 polarity 비율** | **1 : 2 이내** | 아래 참고 — 이 조건이 없으면 응답 습관이 맥락 차이로 둔갑합니다 |

조건을 못 채우면 **아무 말도 하지 않습니다.** 침묵이 추측보다 낫습니다.

> **polarity 균형 조건을 넣은 이유 (Phase A 감사에서 확인)**
> `aligned = centered × polarity`는 **방향**은 보정하지만 **묵종 편향**(무엇에든 동의하는 경향)은 보정하지 못합니다.
> 한 맥락에 `+1` 문항만 몰려 있으면 묵종 성향 응답자는 그 맥락에서만 점수가 높게 나오는데, 이건 맥락 차이가 아니라 **응답 습관**입니다.
> 콘텐츠 규격이 축마다 polarity를 5:5로 맞춘 이유가 이 편향 상쇄인데, 그 균형은 **축 수준에서만** 성립하고 **맥락 수준에서는 깨집니다.**

##### 축별 가용성 (DEC-048 이후 — 기계 산출)

| 축 | 자격 맥락 수 | 비교할 장면 | S4 |
|---|---|---|---|
| `axis-energy` | **2** | 동료 ↔ 혼자 | **가능** |
| `axis-lens` | **3** | 수업 ↔ 생활지도 ↔ 동료 | **가능** |
| `axis-decision` | **2** | 생활지도 ↔ 업무 | **가능** |
| `axis-rhythm` | **3** | 업무 ↔ 수업 ↔ 혼자 | **가능** |

40문항 시점에는 `axis-rhythm` 한 축에서만 가능했습니다. 비어 있던 (장면 × 방향) 칸을 계산해
**8문항을 추가**(DEC-048)하면서 네 축 모두 열렸습니다. 근거는 `docs/content/teacher-style-v1-audit.md` 3·5장입니다.

> 임계값을 넘기려고 태그를 합치지 않았습니다 — 그건 신호를 **발견**하는 게 아니라 **만들어 내는** 것입니다.
> 대신 문항을 더 썼습니다.

> **정직성 한계 명시**: 맥락당 3~6문항입니다. **얇은 근거**이므로 격차가 클 때만, **근거 숫자를 함께 보여 주며** 말합니다. 화면에도 이 한계를 적습니다.

##### 장면 프로파일 — DEC-048로 새로 열린 해석 틀

한 장면 안에 문항 3개 이상인 축이 **둘 이상**이면 그 장면에서 축끼리 견줄 수 있습니다.
네 축을 **세로로** 읽는 기존 틀과 직교하는, **가로로** 읽는 방식입니다.

| 장면 | 견줄 수 있는 축 |
|---|---|
| `lesson` 수업 | 먼저 보이는 것 · 일 굴리는 리듬 |
| `admin` 업무 | 판단 기준 · 일 굴리는 리듬 |
| `colleague` 동료 | 힘을 얻는 방향 · 먼저 보이는 것 |
| `guidance` 생활지도 | 먼저 보이는 것 · 판단 기준 |
| `self` 혼자 | 힘을 얻는 방향 · 일 굴리는 리듬 |

같은 응답으로 **두 방향의 리포트**가 나옵니다. 축을 늘리지 않고 해석 차원을 하나 더 얻는 셈입니다.

#### S5 응답 폭 — 척도를 어떻게 썼는가

48문항 전체에서 척도 사용 분포를 봅니다.

```
extremeRate = (응답값이 1 또는 5인 문항 수) / 48
middleRate  = (응답값이 3인 문항 수) / 48
```

| 스타일 | 조건 | 결과 해석에 주는 영향 |
|---|---|---|
| `wide` | extremeRate ≥ 0.35 | 점수가 크게 벌어지기 쉽습니다. 강도를 조금 낮춰 읽습니다 |
| `moderate` | 그 외 | 기본 |
| `centered` | middleRate ≥ 0.40 | **모든 축이 균형으로 나오는 이유가 성향이 아니라 응답 습관일 수 있습니다** |

**왜 중요한가**: 네 축이 전부 균형으로 나온 선생님께 지금은 "폭넓게 움직이는 리듬"이라고만 말합니다. 하지만 실제 이유가 "가운데를 많이 골랐기 때문"일 수 있습니다. **그 사실을 알려 드리는 것이 정직합니다.** 이 문장은 기존 어떤 검사도 하지 않습니다.

### 4.3 해석 층 L1–L5

신호를 받아 다음 다섯 층으로 조립합니다.

| 층 | 이름 | 입력 | 경우의 수 |
|---|---|---|---|
| **L1** | 좌표 | 축별 연속 `rawScore` | 원자료 — 절대 버리지 않음 |
| **L2** | 기울기 | S1 × S2 = 축당 9상태 | **9⁴ = 6,561** |
| **L3** | 렌즈 | 6개 축쌍 × 4조합 | 24 |
| **L4** | 무게중심 | 축 순위(주축·부축) | 12 |
| **L5** | 유형 | 방향 조합 16개 — 정체성 앵커 | 16 |

여기에 S3(축당 3) · S4(맥락 분화) · S5(3)가 곱해집니다.

> **경우의 수에 관한 정직한 표기**: 명목 조합 수는 수백만이지만, 그 숫자를 자랑하지 않습니다. **"응답 패턴이 다르면 다른 문장이 나온다"** 가 실질적 의미이고, 화면에도 그렇게만 씁니다. 큰 숫자를 내세우는 것 자체가 가짜 정밀도의 한 형태입니다.

### 4.4 L3 — 6개 렌즈

네 축에서 만들 수 있는 축쌍은 6개입니다. 현재 1개만 구현되어 있습니다.

| # | 렌즈 | 축쌍 | 무엇이 보이나 |
|---|---|---|---|
| 1 | 시선과 리듬 | `lens` × `rhythm` | **구현됨** — 무엇을 보고 어떻게 굴리는가 |
| 2 | 힘과 판단 | `energy` × `decision` | 어디서 힘을 얻는 사람이 무엇을 기준으로 정하는가 |
| 3 | 힘과 시선 | `energy` × `lens` | 사람에게서 얻는 힘이 무엇을 향하는가 |
| 4 | 힘과 리듬 | `energy` × `rhythm` | 힘의 방향이 일의 속도를 어떻게 바꾸는가 |
| 5 | 시선과 판단 | `lens` × `decision` | 본 것을 어떤 기준으로 정리하는가 |
| 6 | 판단과 리듬 | `decision` × `rhythm` | 기준이 실행 속도를 어떻게 잡는가 |

**표시 조건**: 두 축이 **모두 방향성(directional)** 일 때만 보여 줍니다. 한쪽이라도 균형이면 그 렌즈는 통째로 숨깁니다(DEC-046 계승, `axisCombination.ts`에 이미 구현된 규칙).

### 4.5 L4 — 무게중심 (축 순위)

`|rawScore|`가 가장 큰 축이 **주축**, 두 번째가 **부축**입니다.

> **"순위 금지"와 충돌하지 않는 이유**: `AGENTS.md` 6절이 금지하는 순위는 **사람과 사람 사이의 서열**(백분위·등급)입니다. 여기서 매기는 순위는 **한 사람 안에서 어느 관점이 더 도드라지는가**로, 비교 대상이 자기 자신입니다. 화면에도 "내 안에서"라고 명시합니다.

**표시 조건**: 1위와 2위의 `|rawScore|` 차이가 **3 이상**일 때만 "주축"이라고 부릅니다. 차이가 그보다 작으면 "비슷하게 도드라지는 두 관점"으로 서술합니다.

### 4.6 L5 — 16 유형 (유지)

유형 이름과 엠블럼은 **정체성 앵커**로 남깁니다. 연수 현장에서 "저는 ○○형이에요"라고 말할 수 있는 손잡이가 필요합니다.

다만 **유형이 결정하는 범위를 줄입니다.**

| 항목 | 현재 | 변경 후 |
|---|---|---|
| 제목 · 한 줄 설명 | 유형 고정 | 유형 고정 (유지) |
| 엠블럼 | 유형 고정 | 유형 고정 (유지) |
| 교직 리듬 | 유형 고정 | **축별 서술 4문장 조립** |
| 장면·협업·행동 문구 | 유형 고정 | **신호 기반 조립** |

## 5. 신뢰 장치 — "알맹이"의 실체

전문성은 문장을 어렵게 써서 생기지 않습니다. **기존 검사가 하지 않는 네 가지**를 합니다.

| # | 장치 | 화면에서 하는 일 | 왜 차별점인가 |
|---|---|---|---|
| **T1** | **근거 노출** | 해석 카드마다 "이 말이 어느 축 몇 점, 몇 문항에서 나왔는가"를 답니다 | "왜 이런 말이 나왔지?"에 답하는 검사가 없습니다 |
| **T2** | **확신도 표시** | S3·S5를 반영해 이 해석이 얼마나 단단한지 밝힙니다 | 보통은 모든 문장을 같은 확신으로 말합니다 |
| **T3** | **반증 여지** | "이 설명이 안 맞는다면 —" 문구로 반박할 길을 엽니다 | 반박할 수 없는 결과는 점괘입니다 |
| **T4** | **측정 범위 고지** | 재지 않은 것을 한 번, 분명히 (`scopeNote` 계승) | 보통은 슬쩍 넘어갑니다 |

### T3 문구 규격

각 주요 카드 하단에 답니다. 형식:

```
이 설명이 안 맞는다면 — {반증 조건}
```

예시(축 · 방향별로 콘텐츠가 소유):

- "최근 한 달이 유난히 바빴다면, 평소 모습이 아니라 그 시기가 답에 실렸을 수 있어요."
- "학년이나 업무가 올해 크게 바뀌었다면 지금 답과 작년 답이 다를 수 있어요."

### T2 확신도 산출

```
S3 = split        → 확신도 낮음
S5 = centered     → 확신도 낮음
S2 = balanced     → 확신도 낮음 (방향 단정 안 함)
그 외             → 확신도 보통 / 높음
```

확신도가 낮으면 **단정형 문장을 쓰지 않고**, 카드에 그 이유를 함께 답니다.

## 6. 채점과 구간 — DEC-047 초안

> **상태**: `PROPOSED` — 사용자 승인 필요 (`AGENTS.md` 1.4 · DEC-046이 승인 없이 금지한 항목)

### 6.1 결정 내용

`|rawScore|` 범위는 축당 **0~24**입니다(DEC-048로 축당 12문항). 3구간을 **5구간**으로 세분합니다.

| id | 라벨 | 범위 | directional |
|---|---|---|---|
| `balanced` | 균형 | **0 – 5** | **false** |
| `leaning` | 조금 뚜렷 | 6 – 10 | true |
| `clear` | 뚜렷 | 11 – 14 | true |
| `strong` | 강함 | 15 – 19 | true |
| `defining` | 매우 뚜렷 | 20 – 24 | true |

### 6.2 균형 경계 0–4를 그대로 두는 이유

**이 경계만이 "방향을 단정할지 말지"를 가르는 안전장치입니다**(DEC-046). 나머지 두 구간만 넷으로 쪼개면 **안전성은 그대로 두고 해상도만 올라갑니다.**

균형 구간을 좁히면 약한 근거로 방향을 단정하게 되어, 참고 자료가 경고한 바로 그 오류(중간치 근처를 유형으로 배정하는 것)를 저지르게 됩니다.

### 6.3 언어 규율 — 5구간을 안전하게 쓰는 방법 ★

> **구간이 올라가면 "얼마나 확신하는가"가 아니라 "몇 개의 장면에서 관찰되는가"가 올라갑니다.**

| 구간 | ✗ 틀린 방식 (확신 상승) | ✓ 옳은 방식 (구체성 상승) |
|---|---|---|
| `leaning` | "조금 그런 편입니다" | "회의 장면에서 이런 모습이 있었을 수 있어요" |
| `clear` | "그렇습니다" | "회의와 수업 준비에서 같은 선택이 보입니다" |
| `strong` | "많이 그렇습니다" | "여러 장면에서 같은 선택이 반복됩니다" |
| `defining` | "확실히 그렇습니다" | "회의·수업 준비·급한 대응 **세 장면 모두에서** 같은 선택이 나타납니다" |

**이 규율이 검증 데이터 없이도 5구간을 정당화합니다.** 구간은 서술의 **범위**를 바꾸지, 주장의 **강도**를 바꾸지 않습니다.

`realContent.test.ts`에 **금지 표현 검사**를 추가해 기계적으로 강제합니다(12.2).

### 6.4 마이그레이션 — 반드시 처리

`intensityBandId`는 **저장된 스냅샷 안에 들어 있습니다**(`src/domain/assessment/scoring/score.ts:16`).

구간 id가 바뀌면 `src/domain/assessment/result/narrative.ts:62`의 조회가 실패해 **기존 결과가 전부 `fallbackNarrative`로 떨어집니다.**

> **해법**: 저장된 `intensityBandId`를 신뢰하지 않고, **보존된 `rawScore`로 읽는 시점에 재계산**합니다.
> `resolveIntensity()`(`src/domain/assessment/scoring/scoring.ts:52`)가 이미 순수 함수이므로 그대로 재사용합니다.

### 6.5 버전 정책

| 버전 | 처리 | 이유 |
|---|---|---|
| `assessmentVersion` | **3 → 4** | DEC-048로 문항이 40 → 48개가 되었습니다 |
| `scoringVersion` | **유지** | `rawScore` 계산식은 그대로입니다 (문항 수만 늘어남) |
| `contentVersion` | **3.1.0 → 4.0.0** | 문항·구간·문구·해석 구조가 바뀝니다 |

> **재검사가 필요합니다.** 문항이 늘었으므로 기존 응답으로는 새 점수를 만들 수 없습니다(DEC-048).
> 그래서 **재검사를 유발하는 변경을 이 개편에 전부 몰아넣습니다.** 나누어 배포하면 재검사를 두 번 요구하게 됩니다.

`intensityBandId` 재계산(6.4)은 그럼에도 필요합니다. 앞으로 문구만 바뀌는 개정에서
저장된 결과가 조용히 깨지지 않게 하는 안전장치이기 때문입니다.

## 9. 인포그래픽·차트 시스템

`dataviz` 방법론에 따라 **형태를 먼저 고르고 색을 마지막에** 정했으며, **팔레트는 눈으로 판단하지 않고 검증기로 계산했습니다.**

### 9.1 형태 — 데이터가 하는 일에 맞춥니다

| 무엇을 보여주나 | 형태 | 비고 |
|---|---|---|
| 축 하나의 방향 + 세기 | **발산 막대** (중앙 0 기준) | **주 형태.** 양극 데이터의 정직한 표현 |
| 네 축의 세기를 한눈에 | **레이더(다이아몬드)** — `\|rawScore\|`를 4스포크에 | **보조.** 아래 주의 |
| 두 축이 만난 자리 (L3) | **사분면 산점도** — 두 축을 x·y로, 내 위치를 점으로 | **신규.** "두 축이 만났을 때"를 직접 그림으로 |
| 축 순위 (L4) | **정렬 막대** | "내 안에서" 명시 |
| 맥락 분화 (S4) | **덤벨 차트** — 맥락별 평균을 점으로, 격차를 선으로 | **신규.** 격차 자체가 메시지 |
| 축 내 흩어짐 (S3) | **점 분포(스트립)** — 12문항을 점 12개로 | **신규.** 일관/갈림이 한눈에 |
| 유형 정체성 (L5) | **엠블럼** — 기존 `TypeEmblem`(DEC-039) 확장 | 보내 주신 다이아몬드 이미지는 **차트가 아니라 이 계열**입니다 |

> **레이더에 관한 정직한 단서**
> 레이더는 면적이 값의 **제곱**으로 커져 차이를 과장하고, 스포크 순서를 바꾸면 모양이 달라집니다. 또 우리 축은 양극이라 `|rawScore|`만 그리면 **방향이 사라집니다.**
> → 레이더는 **"세기 지도"라는 보조 개요**로만 쓰고, 정확한 읽기는 발산 막대가 맡습니다. 스포크마다 방향 라벨을 직접 답니다.

### 9.2 색 — 검증 완료

먼저 확인된 사실입니다.

```
현행 --color-perspective-{sprout,ochre,berry,slate}  →  FAILED (5개 검사 중 3개 실패)

  [FAIL] 채도 미달        4색 모두 C < 0.10 — 차트 마크로는 회색으로 읽힘
  [FAIL] CVD 분리        berry↔sprout ΔE 2.9 (적록색약에서 거의 동일)
  [FAIL] 일반 시야 분리   slate↔sprout ΔE 8.9 (정상 색각도 구별 어려움)
```

에디토리얼 잉크로 만든 색이라 **데이터 마크로는 채도가 모자랍니다.** 대체안 셋 모두 검증을 통과했습니다.

| 용도 | 값 | 검증 결과 |
|---|---|---|
| **발산 쌍** (축 막대 · 주 encoding) | `#00713e` ↔ `#c06f0a`, 중립 = 샌드 | **ALL PASS** (CVD ΔE 7.9 → 라벨 병기 필수) |
| **순차 램프** (강도 4단계) | `#8cb395` · `#5d996e` · `#307e4b` · `#00612c` | **ALL PASS** |
| **레이더 4색** (네 축 겹칠 때만) | `#00682e` · `#da950b` · `#ae4090` · `#2580c1` | **ALL PASS** (적록 회피, 오커는 라벨 필수) |

> **왜 네 축에 네 색을 기본으로 쓰지 않는가**
> 축의 일은 *정체성*이 아니라 **양극성**입니다. 네 축 전부에 **같은 발산 쌍**을 쓰고 축은 **라벨·아이콘·위치**로 구분하는 편이 더 정직하고, 적록 문제도 원천적으로 사라집니다.
> 4색은 레이더처럼 **한 그림에 네 축을 겹칠 때만** 씁니다. `AGENTS.md`의 "색만으로 상태 전달 금지"와도 맞물립니다.

**재검증 의무**: 색을 바꾸면 아래를 다시 돌리고 결과를 첨부합니다.

```bash
node scripts/validate_palette.js "<hex,hex,…>" --mode light --surface "#fcfbf8" --pairs all
```

### 9.3 균형 상태의 시각 표현

균형(`balanced`)은 **회색이나 빈 상태로 그리지 않습니다.** 결함처럼 보입니다.
중립 색의 **넓은 띠**로 그려 "이 구간 어딘가"를 뜻하게 하고, 점 하나로 찍지 않습니다.

### 9.4 설계값 표기

S3·S4의 경계값(0.8 / 1.8 / gap 1.5 / 최소 3문항)과 6장의 구간 경계는 **설계값**입니다.
검증된 절단점이 아니며, `docs/content/teacher-style-v1-validation.md`에 그렇게 기록합니다.

그래서 신호를 스냅샷에 넣지 않고 **읽을 때마다 원본 응답에서 다시 계산**합니다.

| 얻는 것 | 설명 |
|---|---|
| 스냅샷 형식 불변 | 저장 구조를 바꾸지 않으므로 마이그레이션이 필요 없습니다 |
| 예전 결과도 함께 좋아짐 | 계산 방법을 개선하면 이미 검사한 사람의 결과에도 바로 반영됩니다 |
| 원칙 일치 | `getResult`가 이미 "원자료 보존 + 현재 로직으로 재계산" 방식을 씁니다 |

#### 경계값을 비율로 둔 이유

`AGENTS.md` 1.3은 엔진에 검사별 숫자를 박는 것을 금지합니다.
분산 경계 `0.8 / 1.8`과 격차 기준 `1.5`는 **5점 척도에서만** 맞는 값이므로, 척도에서 계산되는 비율로 두었습니다.

```
최대 편차(d)    = 척도에서 계산 (5점이면 2, 7점이면 3)
최대 분산       = d²
steady          ≤ 0.20 × d²      (5점에서 0.8)
mixed           ≤ 0.45 × d²      (5점에서 1.8)
장면 격차 기준   ≥ 0.75 × d       (5점에서 1.5)
```

7점 척도로 바꿔도 구간의 뜻이 유지되는지 테스트가 확인합니다.

| 구간 | 이전 (확신 사다리) | 이후 (구체성 사다리) |
|---|---|---|

| `strong` | ~경향이 매우 뚜렷해요 | **장면이 바뀌어도** … |
| `defining` | — | **대부분의 장면**에서 … |

문구는 나중에 손대기 쉬우므로 **테스트가 규율을 강제합니다.**

- 확신 표현(`확실히`·`틀림없이`·`매우 뚜렷해` 등) 금지
- 구간마다 정해진 장면 범위 표현이 실제로 들어 있는지 확인
- 균형 구간은 `두 방식`/`비슷하게`로 방향을 단정하지 않는지 확인
- 축마다 반증 문구가 있는지 확인
